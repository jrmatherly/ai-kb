# v0.8.2 Release Notes

Release date: 2026-09-24

v0.8.2 takes the agent out of the chat box: it can drive the browser on your computer, knowledge bases can be published as an MCP server to Claude, Cursor and other AI tools, and conversations are easier to steer, with mid-run follow-ups, forks and rollbacks. The sandbox gains an interactive terminal and a graphical desktop, model setup now configures itself from a provider catalog, and the release adds Confluence and DingTalk Docs data sources and a Japanese UI.

Before upgrading from v0.8.0, read the [upgrade notes](#upgrade-notes). The full list of changes is in the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

## Local Browser {#local-browser}

Smart Reasoning conversations can drive Chrome or Edge on your computer directly. The browser connects to AI KB through Tencent's open-source [BrowserSkill](https://github.com/Tencent/BrowserSkill) extension. The agent opens pages in a dedicated task window, clicks, fills in forms and reads content, then reports the results back in the conversation.

<Screenshot
  src="/screenshots/local-browser-task.png"
  caption="The agent looks up the latest GitHub release, then fills in an order form. The task preview is at the bottom right of the conversation" />

- **Controlled from the conversation**: the task preview shows in the conversation. You can pause, resume or end it at any time, or jump to the matching page in the browser.
- **Hands off to you when needed**: at a login, a CAPTCHA or a step that needs authorization, the agent asks for human help. Once you finish in the browser, it continues.
- **Pair once, use everywhere**: copy the pairing link in Toolbox → Browser connection and paste it into the extension. Conversations in the same workspace share this browser's authorization, and it is used only after you turn on the Local Browser switch in the input box.

<Screenshot
  src="/screenshots/browser-connection.png"
  caption="Toolbox → Browser connection: extension version, connection status and the web actions the agent can perform" />

The app image for Docker deployments bundles the BrowserSkill service and its extension, so there is usually nothing extra to configure. Multi-replica deployments need an inter-node address and a shared secret. See [Local Browser](../05-clients/09-local-browser.md).

## Built-in MCP Server {#mcp-server}

Each workspace can publish its knowledge bases as an MCP service, so MCP clients such as Claude Desktop, Cursor, Claude Code and VS Code can search and ask questions directly, with no separate MCP process to deploy.

<Screenshot
  src="/screenshots/mcp-server-endpoint.png"
  caption="Settings → Publish & Integrations → MCP Server: endpoint address and client configuration" />

- Create an endpoint in Settings → Publish & Integrations → MCP Server, then pick the knowledge bases it can reach and the tools it exposes.
- Tools come in four groups: search and reading, Q&A (runs the agent the endpoint names), Wiki, and write. Write tools are off by default.
- Each endpoint has its own token and rate limit (60 calls per minute by default), and the token can be rotated at any time.
- The page gives ready-made configuration snippets for Cursor, VS Code and Claude Desktop, and a one-line command for Claude Code.

The Python `mcp-server/` in the repository is marked deprecated. See [MCP integration](../03-features/08-mcp.md#serving-external-clients).

## Conversation control {#conversation-control}

<Screenshot
  src="/screenshots/chat-steer-queue.png"
  caption="Follow-up instructions queued above the input box while an answer is in progress" />

- **Follow-ups mid-run**: you can keep typing while the agent is still working. Enter queues the message for when the current step ends. ⌘Enter / Alt+Enter inserts it into the current task right away.
- **Fork and roll back**: fork a new conversation from any earlier question, or roll back in place to an earlier question. Conversations that use a sandbox also restore the workspace as it was at that point.
- **Reasoning effort**: each conversation can choose the model's reasoning effort on its own.
- **Truncation notice**: an answer cut off by the output limit is now clearly marked instead of being truncated silently.

<Screenshot
  src="/screenshots/artifacts-library.png"
  caption="The Artifacts page in the sidebar: files the agent generated, collected across conversations" />

Files the agent generates are collected on the Artifacts page in the sidebar. You can filter by type, search, view earlier versions and delete files you no longer need. When you save an answer to a knowledge base, the editor is now a split Markdown source and preview view, and drafts can be saved.

## Sandbox: graphical desktop, interactive terminal and local sandbox {#sandbox}

The sandbox panel on the right of the conversation gains Desktop and Terminal tabs, which open the same sandbox the agent is using.

<Screenshot
  src="/screenshots/sandbox-desktop.png"
  caption="Graphical desktop: use the desktop environment inside the sandbox from the browser" />

<Screenshot
  src="/screenshots/sandbox-panel-terminal.png"
  caption="Interactive terminal: inspect workspace files and command output" />

- **Graphical desktop**: needs a Cube or E2B desktop template, with the desktop turned on in the sandbox configuration.
- **Interactive terminal**: available on Cube and E2B sandboxes. After a page refresh you can reattach to a terminal that is still running.
- Opening the panel does not create or wake a sandbox. It disconnects after a period of inactivity, 900 seconds by default.
- When the agent runs commands or installs skills, the tool card shows the output live.

**Local sandbox in the Lite desktop edition (macOS)**: conversations without a remote sandbox run commands in the system sandbox. A new conversation can be bound to a project folder on your computer, and the agent can write only to that folder. Commands have no network access, `.git` directories are read-only and credential directories are never accessible.

**Toolbox**: skills, MCP services and the browser connection move from Settings to the Toolbox in the sidebar. The old Settings entries redirect automatically.

## Model setup {#models}

Model setup is now organized in three layers: protocol, provider and model catalog, with 27 built-in providers. When you add a model:

- Picking a model from the provider catalog fills in the context window, maximum output, reasoning effort and vision capability.
- The "how it is called" panel shows the request protocol, request URL and optional reasoning effort this model will use.
- When an endpoint differs from the defaults, you can override the protocol in the advanced options or provide protocol-compatibility JSON.
- Speech recognition covers every provider whose documentation offers it.

## Knowledge bases and data sources {#knowledge}

- **Confluence data source**: supports Cloud and Server / Data Center, syncs published pages per space, updates incrementally and has deletion protection.
- **DingTalk Docs data source**. Tencent IMA sync now walks subfolders.
- **Upload and parsing**: the upload panel shows overall progress and supports cancel and retry. The parsing timeline shows the time spent in each stage and the reason for a failure. Documents with no progress for a long time are marked Queued or May be stuck.
- **Lists and downloads**: document and resource lists can be sorted, and original files can be downloaded in bulk as an archive.
- **Other**: document summaries can be turned off at upload. A knowledge base description can be generated from document profiles. FAQs can be filtered by enabled status. The activity log shows the name of the API key used for an action.

## Integrations, UI and security {#platform}

- **Web search**: adds Bocha and Serply. Brave and Serply support region and freshness filters.
- **IM**: each channel can set its own reply language.
- **Japanese UI**: the UI adds Japanese. Switch to it in the UI, or make it the default with `DEFAULT_LOCALE`.
- **CLI setup page**: Settings → Publish & Integrations → CLI walks through installation and login in three steps.
- **Administrator-created users**: system administrators can create accounts directly in the console, generate a one-time password and copy the account details.
- **Allowlist-only egress**: with `SSRF_DNS_WHITELIST_ONLY=true`, domains not in `SSRF_WHITELIST` are rejected before DNS resolution. This suits offline or tightly controlled deployments on your own infrastructure.

## Upgrade notes {#upgrade-notes}

| Change | What to do |
| --- | --- |
| `.env.example` no longer ships default values for `JWT_SECRET` and `SYSTEM_AES_KEY`, and adds `SYSTEM_SIGNING_KEY` | New deployments must generate their own. **Existing deployments must keep their original `SYSTEM_AES_KEY`**, or saved credentials can no longer be decrypted. If `JWT_SECRET` is unset, each process generates a random one, so logins are lost on restart and cannot be shared across replicas |
| The DingTalk IM channel supports Stream mode only | Migration `000096` switches webhook channels to Stream automatically. Turn on Stream mode for the app in the DingTalk developer console |
| Commands in the sandbox run as `root` by default (uid 1000 in v0.8.0) | Each conversation has its own sandbox, and the isolation boundary is still the container. Adjust scripts that depend on a non-root user |
| When you update an MCP service and pass `usage_instructions`, it must be non-empty text of at most 16000 characters | Omit the field to keep the existing instructions |
| Organization invitations can look up a workspace only by its exact ID | Searching workspaces by name is no longer supported |
| In the Go SDK, `UpdateAgentRequest.Avatar` becomes `*string` | `nil` keeps the avatar, an empty string clears it |

Database migrations: `000091`-`000110` for PostgreSQL, `000013`-`000030` for SQLite. `000106` creates an index with `CONCURRENTLY`. If it is interrupted, drop the invalid index before running the migration again; see [Troubleshooting](../01-getting-started/05-troubleshooting.md). The ParadeDB image has been upgraded and runs on CPUs without AVX2. The MinIO image is now pulled from `quay.io`.

## Other improvements and fixes {#other-changes}

- **Agent**: the retrieval tools are merged into `search_knowledge`, `read_document` and `list_documents`. Old tool names map automatically, so no configuration needs migrating. Conversation history is trimmed to the model's context window, and compression checkpoints persist across turns. MCP tools are now discovered and called on demand, each service's tool catalog is persisted, and individual tools can be enabled or disabled.
- **Skills**: upgrading an older skill no longer rolls back its directory or takes it offline mid-upgrade. Runtime dependencies are checked after installation.
- **Wiki**: a full-page rewrite that gets truncated is continued. Entries with the same name reuse a page across types. Cited chunks carry their image captions.
- **Retrieval and parsing**: Milvus supports multilingual BM25. Neo4j queries have a limit guard. The PaddleOCR-VL request timeout is configurable. PDFs still use the built-in parser by default when anydoc is linked. Inline HTML tables no longer produce oversized chunks.
- **Stability**: fixes several cases of documents stuck in Processing or Deleting. Closes paths for cross-workspace access in shared workspaces. Wiki tasks for deleted tenants no longer call models. Request formats for embedding, rerank and some chat providers now match their official documentation.

The full list is in the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

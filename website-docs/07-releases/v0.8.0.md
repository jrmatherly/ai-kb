# v0.8.0 Release Notes

Release date: 2026-09-03

The theme of v0.8.0 is letting the agent actually get work done. Skills become a resource managed per workspace, and they run scripts, process files and produce deliverables in a per-conversation sandbox. New cross-conversation long-term memory lets the agent remember preferences and facts you have confirmed. Office documents can also be parsed inside the app, and the release adds GitLab and Tencent IMA data sources, LiteLLM model access and the DeepSeek Harness plugin.

Before upgrading from v0.7.x, read the [upgrade notes](#upgrade-notes). The full list of changes is in the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).

## Skill sandbox {#skill-sandbox}

Agent skills run in a per-conversation sandbox: each conversation has its own sandbox, and multi-turn tasks share the same workspace. Running commands, reading, writing and editing files, processing uploaded attachments and collecting generated files all happen in that workspace.

<Screenshot
  src="/screenshots/skill-sandbox-chat.png"
  caption="The agent generates a Word document from the knowledge base and previews the generated file next to the conversation" />

- **Three backends**: Docker (single host or self-hosted), E2B (cloud, or a self-hosted E2B-compatible control plane) and CubeSandbox, all using the same remote protocol.
- **Configured per workspace**: image, CPU / memory, lifetime, DNS, templates and snapshots can all be configured per workspace. Administrators can also set a network policy for each configuration, such as denying egress by default or allow / deny lists.
- **Docker backend off by default**: mounting `docker.sock` is equivalent to root on the host. Turn it on in System Settings → Network Security, or set `WEKNORA_SANDBOX_DOCKER_ENABLED=true`.
- **Generated files**: files generated in the sandbox are collected in each message's Artifacts drawer, where they can be previewed and downloaded. New files trigger a notice.
- **Long-task compression**: long-running tasks in the sandbox compress the tool-call history instead of truncating or rewriting files. A stable prompt prefix with cache markers raises the cache hit rate on Anthropic and OpenAI-compatible endpoints. Token usage is also recorded for each turn.

See [Skills catalog and sandbox](../03-features/22-skills-sandbox.md) and [Sandbox deployment and troubleshooting](../06-development/04-sandbox-deployment.md).

## Workspace skill catalog {#skill-catalog}

Skills become first-class resources in the workspace instead of files next to the server process.

<Screenshot
  src="/screenshots/skill-catalog.png"
  caption="Workspace skill catalog: each skill and the sandboxes it is installed in" />

- **Several install sources**: ClawHub, SkillHub / skills.sh, GitHub / GitLab links, or a ZIP upload.
- **Installed per sandbox**: each installation creates a snapshot on the chosen sandbox configuration, with live install progress and an install history. An installation can be stopped and rerun. Uninstalling from a sandbox keeps the package in the catalog.
- **View and edit online**: the files of installed skills can be browsed and edited in Settings. The agent can also change skill files with `write_skill_file` and `edit_skill_file`, and `shell_exec` no longer requires a skill to be installed first.
- **Environment variables**: personal and workspace-level skill environment variables are injected at execution time and cannot be read back once saved.
- Mentioning a skill with `@` no longer unexpectedly narrows the set of skills the agent can use.

## Cross-conversation long-term memory {#memory}

A new long-term memory capability, separate from the Neo4j-based conversation memory removed in v0.7.1.

- **Opt-in**: once a workspace turns it on, each user can still turn it off for themselves.
- **Categorized memory**: memories fall into five categories (profile, preference, fact, item and interest). They can be written explicitly or extracted automatically in the background.
- **You confirm**: memories inferred automatically stay pending until you confirm them and do not take effect before that.
- **How it is used**: profile and preference memories go into every turn. Situational facts are recalled by keyword, and semantic recall can be turned on. The agent can query on demand with `search_memory`. Frequently cited documents get a higher weight in retrieval.
- Settings, entries, topics, document links, confirm / reject, export and forced consolidation are all served under `/api/v1/memory/*`, only for full-permission API keys, and always act on the caller's own data.

See [Long-term memory](../03-features/23-memory.md) and [Long-term memory API](../04-api/02-api-memory.md).

## Document parsing and data sources {#parsing-and-sources}

- **In-app anydoc parsing**: Office documents that anydoc can convert, such as doc, docx, ppt and pptx, are parsed directly in the Go app instead of going through docreader. The app image links anydoc by default.
- **XMind outline parsing**: `.xmind` files are parsed into an outline and indexed like any other document.
- **Automatic document tagging**: after parsing, the chat model can pick suitable tags from the knowledge base's existing tags and add them incrementally. It never creates new tags or overwrites tags added by hand.
- **GitLab and Tencent IMA data sources**: GitLab projects can be synced as a knowledge source. Tencent IMA notes sync through the notes OpenAPI and retry automatically on transient errors.
- **Parsing quality**: vertically merged cells and table text in DOCX are preserved. Images embedded in PDFs no longer come out solid black. A failed web fetch now reports an error instead of importing the error page into the knowledge base.

See [Document parsing](../03-features/03-document-parsing.md) and [Data source import](../03-features/10-datasource.md).

## Models, search and ecosystem {#ecosystem}

- **LiteLLM**: a first-class provider for chat, embedding and rerank models. One gateway address can route to several upstream models.
- **Exa and Metaso search**: two new web search providers.
- **DeepSeek Harness plugin**: the official npm package [`@wxg-prc-cpg/dsh-weknora`](https://www.npmjs.com/package/@wxg-prc-cpg/dsh-weknora) provides four read-only tools, `weknora_search`, `weknora_read_document`, `weknora_ask` and `weknora_list_knowledge_bases`, so the DeepSeek Harness coding agent can search knowledge in AI KB. See [DeepSeek Harness](../05-clients/08-deepseek-harness.md).

## Chat experience {#chat}

- Longer conversations show a question outline for quick navigation, and messages are separated by time.
- `shell_exec` is shown as a "command + output" card. Tool cards show the sandbox file list and the skill name.
- Mermaid diagrams stay rendered during streaming instead of flickering.

## Accounts and security {#security}

- **OIDC signature verification**: ID tokens are verified against JWKS. The new `/auth/oidc/start` redirects straight to login.
- **Optional complex passwords**: when turned on, registration, password changes and administrator password resets all require upper- and lowercase letters, digits and special characters (`WEKNORA_AUTH_COMPLEX_PASSWORD_ENABLED` or System Settings).
- **Administrator-created users**: platform administrators can create users directly in the console, with no invitation link needed.
- **Invitation flow**: invitations to already registered users can be accepted automatically. In invite-only mode, a share link first takes the visitor through login and then into the workspace.
- **Sandbox security**: everything in the Docker sandbox runs as the sandbox user (uid 1000). Symlink operations that could escape the workspace are closed off, and zombie processes left by cancelled executions are reaped.

## Upgrade notes {#upgrade-notes}

| Change | What to do |
| --- | --- |
| The host-process (Local) sandbox backend is removed | Recreate existing Local sandbox configurations with Docker (must be turned on manually), E2B or Cube |
| The Docker sandbox backend is off by default | Turn it on in System Settings → Network Security, or set `WEKNORA_SANDBOX_DOCKER_ENABLED=true` |
| With complex passwords on, registration and password-change requests that break the rules are rejected | Tell users about the new password requirements before turning it on |

Database migrations: `000080`-`000090` for PostgreSQL, `000003`-`000012` for SQLite. The Docker sandbox backend requires `appuser` in the app container to belong to the group that owns `docker.sock`.

## Other improvements and fixes {#other-changes}

- **Retrieval**: MMR selection is computed incrementally. Hybrid retrieval respects `resource_urls=public`. `MatchCount=0` no longer truncates all results. Deleted images are no longer retrieved.
- **IM**: Feishu long connections work behind a reverse proxy, and streaming cards show progress in full-output mode. Several compatibility improvements for WeCom, DingTalk and Yunzhijia. IM Q&A supports file attachments.
- **Workspaces and documents**: switching workspaces remembers the last one used. Passwords can be changed in personal settings. Drag-and-drop folder upload keeps the folder structure. Document summaries are editable, and chunk lists are paginated.
- **Deployment capabilities**: modules that are not registered are hidden from menus and settings (`GET /system/capabilities`), so Lite and other slimmed-down editions no longer show missing features.
- **Fixes**: high-risk system settings read the most recently saved value. Feishu streaming cards no longer get stuck in progress. Deleting a model that is still referenced shows the reference details. Shared knowledge bases no longer show a document count of 0 in the agent context. Built-in agent names and descriptions follow the UI language.

The full list is in the [CHANGELOG](https://github.com/Tencent/WeKnora/blob/main/CHANGELOG.md).
